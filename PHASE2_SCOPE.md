# Phase 2: Hardware RTL Implementation & Simulation

## Goal
Implement a synthesizable SystemVerilog BNN inference engine that exactly matches the software model, with automated verification against the trained weights.

## Scope
Only touch the following:
- RTL implementation: `hw/rtl/bnn_top.sv`, `hw/rtl/bnn_layer.sv`, `hw/rtl/popcount.sv`, `hw/rtl/bnn_pkg.sv`
- Memory initialization: `hw/mem/` (auto-generated from export)
- Simulation: `hw/sim/bnn_tb.sv`, `hw/sim/run_sim.sh`
- Verification scripts: `scripts/verify_hw.py` (compare HW vs SW outputs)
- Configuration: `configs/hardware.yaml` (timing, parallelism, memory mapping)

## Out of Scope
- Vivado project generation (Phase 3)
- FPGA synthesis/implementation (Phase 3)
- Timing closure (Phase 3)

## Acceptance Criteria
- [ ] RTL compiles cleanly with `iverilog` and `verilator`
- [ ] RTL simulates correctly with `iverilog` + testbench
- [ ] Hardware output matches software output for all 40 test images (100% match)
- [ ] Hardware output matches software output for `my_digit.png` (correct classification)
- [ ] No hardcoded paths - all configurable via `configs/hardware.yaml` and `configs/default.yaml`
- [ ] Memory files auto-generated by `scripts/export.py` (already done in Phase 1)
- [ ] Clean, modular SystemVerilog with parameterized layers
- [ ] Proper reset/start/stop FSM with `done` signal
- [ ] Resource-efficient design (sequential layer processing, shared popcount)

## Architecture Notes
- Use sequential layer processing (not fully parallel) to save LUTs/BRAMs
- Each layer: `BinarizeLinear` → `BatchNorm` → `Hardtanh` (except output: just BatchNorm)
- Weights stored as packed bits in memory (hex format from export)
- Thresholds stored as fixed-point or float in memory
- Use popcount + compare for dot product: `sum(w_i * x_i) > threshold`
- Input: 784 bits (1 bit per pixel, packed)
- Layer 1: 256 neurons, Layer 2: 256 neurons, Layer 3: 10 neurons
- All memory reads through single-port BRAM interface
